Learn SketchNet

A beginner-friendly guide to SketchNet and the SketchMod editor.

Sections

Quick Start

You need a free SketchNet account to build models in SketchMod. Public models can be viewed and exported without signing in — open any public model and click View graph. Once signed in, follow these four steps to create your own model.

1. Add your data

Upload a dataset under Data, or pick one when you configure an Input Data node in SketchMod. See for upload formats, public vs private datasets, and attaching data.

2. Draw the graph

Open SketchMod, place nodes from the left toolbar, and connect output ports (right) to input ports (left). Every trainable model needs Input Data, at least one layer, an Output, and an Optimizer. See for how connections and phase checkboxes work.

3. Check the graph

Click Check. SketchNet validates connections, shapes, and phases before anything is exported. Fix any errors shown in the dialog. Use for Check, phase highlighting, and shortcuts.

4. Export PyTorch code

Click Export to download a .py file or a .zip bundle (script plus dataset). The generated script has four clear parts: load_data(), Model, train(), and evaluate() — no hidden dictionaries or runtime branching.

Ports & Flow

A SketchNet graph is a diagram of nodes (operations) connected by links. Each link runs from an output port on the right of one node to an input port on the left of another. Information flows forward only — data-path loops are invalid (see Help for cycle errors).

Port types

Select a port in SketchMod to see its shape and phase checkboxes in the right sidebar (param ports have no phase boxes).

Data port Colored circle. Carries tensors (features, labels, layer activations). You choose Preprocessing, Training, and/or Evaluation with the checkboxes.
Multi port Purple circle; shows a count when several links attach. Same-phase sources are concatenated. Use this to merge train and test into one layer input.
Role port Diamond on the Output node: loss, labels, prediction, evaluation. Defaults: loss and labels → Training; prediction and evaluation → Evaluation.
Param port Dashed amber/sky link. Shares metadata (normalization stats, category lists) — not the main tensor path. Example: connect Normalize (train) → param → Normalize (test) so test uses train statistics.

How information flows

  1. Phase gate on every link — data crosses a link in a phase only when both ports on that link have that phase checked.
  2. Activation spreads downstream — when a node is active in a phase, connected nodes downstream can activate once their inputs are satisfied.
  3. Two input styles — most nodes need at least one satisfied data input; Optimizer, Add, Accuracy, and Visualization need all connected data inputs satisfied in that phase.
  4. Param links are side channels — they share configuration between nodes; they do not replace marking data ports with the correct phases.
  5. Shapes propagate automatically — each port displays a tensor shape as you build. Check catches mismatches before export; you do not need to compute shapes by hand.

Worked example: binary classification

Main path from raw data to loss. Side paths show labels, optimizer, and the test branch merging at the layer.

Input Data → Column Select → Train / Test Split → Normalize → Layer (multi-input) → Output
Preprocessing — mark split and normalize outputs with Preprocessing (and Training/Evaluation where data should continue).
Training — train branch → purple layer input; labels → Output (loss); Output loss → Optimizer. Check Training on those ports and links.
Evaluation — test branch → same purple layer input; connect prediction/evaluation ports to Accuracy or Visualization. Check Evaluation on the test path.

Next: runtime phases

Those three phase checkboxes control where each port runs in the exported script. Open to see what Preprocessing, Training, and Evaluation do at export time.

How It Works

Each port's phase checkboxes decide which stage it belongs to. SketchNet runs your graph in three stages at export time.

Prepare data Preprocessing

Load CSV/Excel data, split train/test, normalize features, and encode labels. This runs once when the script starts.

Train the model Training

Layers, loss, and the optimizer run here. Data must reach the model through ports that carry the Training phase.

Test the model Evaluation

Accuracy, plots, and predictions run on test data. Use ports marked Evaluation.

One important rule

Training and testing must enter the same layer — connect both train and test tensors to the same input port (purple multi-input ports accept several links). If test data enters at a different layer, evaluation is skipped.

Nodes

Nodes are grouped by what they do. Select a node in SketchMod to edit it in the right sidebar.

Data

  • Input Data — load a dataset or synthetic tensor.
  • Column / Row Select — pick features and labels.
  • Train / Test Split — separate training and test rows.
  • Normalize — scale features (statistics can be shared with test data).
  • OneHot / DeOneHot — encode and decode class labels.
  • Reshape / Flatten — change tensor shape before the model.

Model layers

  • Layer / Neuron — fully connected layer with an activation.
  • Conv2D — convolution for image-like inputs.
  • Dropout / BatchNorm / Add / Concat — regularization, normalization, skip connections, merging branches.
  • Output — defines loss, prediction, and evaluation outputs.

Training

  • Optimizer — loss type, learning rate, epochs, batch size, early stopping.

Loss & labels

Pick the Optimizer loss to match how your labels are encoded. See Help for label-loss-mismatch and optimizer-missing-labels.

Loss (Optimizer) Labels should be Typical use
CrossEntropyLoss 1-D integer class indices (N,) Multi-class classification
BCEWithLogitsLoss One-hot (N, C) Binary / multi-label
MSELoss Float targets (N,) or (N, 1) Regression
  • Use Column Select for the label column; add OneHot only when your loss expects one-hot labels.
  • CrossEntropy + OneHot on labels triggers a Check warning — use integer labels instead.
  • On the Output node: connect loss and labels role ports to the Optimizer; use prediction / evaluation for Accuracy and Visualization.

Results

  • Accuracy — classification score (optional confusion matrix).
  • Visualization — scatter or histogram plots.
  • Print — debug tensor shapes in the console.

Advanced

  • Dim Select — slice along extra dimensions.
  • Param ports — see for dashed param links and metadata sharing.

Starter Templates

Each link opens a ready-made graph in SketchMod. Attach your own dataset to the Input Data node.

  • Linear Regression — predict a number from features (MSE loss).
  • Binary Classification — two-class prediction with CrossEntropy and Accuracy.
  • Image Classifier (CNN) — reshape flat pixels, convolve, classify.
  • Skip Connection — residual-style Add: features skip around a hidden layer.

Data & Export

SketchNet separates data management (upload and share datasets) from export (turn your graph into a runnable PyTorch script).

Upload and attach data

Data dashboard

Sign in and open Data from the navbar. Use the upload modal to add CSV, Excel, or other supported files. Choose Public so anyone can use the dataset, or mark it Private and grant access to specific users.

Input Data node

In SketchMod, add an Input Data node and select your uploaded dataset (or use synthetic data for testing). Tensor shapes appear on ports as the graph is wired. If shape stays unclear, Check may show unclear-data-shape — verify column selection and file format.

Export formats

Export is available from the SketchMod toolbar after your graph passes Check. Invalid graphs cannot be exported.

PyTorch (.py)

Downloads a single model.py script. You supply the dataset separately (same file you attached in Input Data).

PyTorch (.zip)

Downloads a zip containing model.py, your dataset file(s), and requirements.txt (includes scikit-learn when the generated code needs it).

Run locally

After exporting a zip, unzip and run from that folder:

pip install -r requirements.txt python model.py

The script is structured in four parts: load_data() (preprocessing), Model (network), train(), and evaluate() — matching the three phases in . Choose loss and label encoding first in the tab before picking CrossEntropy or MSE.

SketchMod Tools

Use these toolbar features while building a graph — especially when Check reports phase or connection errors.

Check

Click Check in the left toolbar. It runs the same validator as export. Errors block export and must be fixed. Warnings allow export but flag questionable design (e.g. label/loss mismatch). Read the message, then use Highlight Path to see which part of the graph is active.

Highlight Path

Open Highlight Path (eye icon) and pick a phase:

  • Preprocessing / Training / Evaluation — highlights nodes, links, and ports active in that phase.
  • Show All — overlays all phases at once (colored rings on ports).
  • Clear — removes the highlight overlay.

Tip: if Check says the Optimizer is not in the training phase, open Highlight → Training and trace backward to the first link missing the Training checkbox.

Keyboard shortcuts

Press ? in SketchMod to open the shortcuts modal. Common keys:

  • S — Select tool
  • H — Pan tool
  • D — Delete tool
  • Ctrl+Z / Ctrl+Y — Undo / Redo
  • Ctrl+C / Ctrl+V — Copy / Paste nodes

Save model

Use Save to store your graph in the Models Library (name, description, optional cover image). You can reload it later or share view/fork access with other users.

Help

Missing Input Data node

Add an Input Data node — every graph needs a data source.

Missing Output node

Add an Output node when training. Connect your last layer to it.

Optimizer not in training phase

See : the Optimizer must be reachable in the Training phase, with phase boxes checked on every link in that path.

No optimizer / no training loop

Add an Optimizer, connect the Output loss port and your label tensor.

Preprocessing does not reach training or evaluation

Mark at least one preprocessing output port with Training or Evaluation so data can flow forward.

Evaluation cannot reuse the trained model

See : connect train and test data to the same model input port (purple multi-input).

Data-flow or param-port cycle

See : remove a link that creates a loop. Data flows forward only; param links (dashed) must not circle back.

Model does not learn

See : check label column, loss type, learning rate, epochs, and that CrossEntropy expects 1-D integer labels.

Check error glossary

Messages from Check include a stable code. Errors block export; warnings do not.

Errors (export blocked)
  • missing-input — Fix: Add an Input Data node.
  • missing-output — Fix: Add an Output node; connect your last layer to it.
  • data-flow-cycle — Fix: Remove a data-path loop. See Ports & Flow.
  • param-cycle — Fix: Remove a param-port loop (dashed links).
  • optimizer-not-training — Fix: Enable Training on every port/link from data to Optimizer. Use Highlight → Training.
  • optimizer-missing-labels — Fix: Connect Output labels role port to Optimizer.
  • optimizer-missing-loss — Fix: Connect Output loss role port to Optimizer.
  • model-input-missing — Fix: Mark Training on ports so data reaches model layers.
  • missing-input-connection — Fix: Connect all required inputs (Add, Concat, etc.).
  • batch-size-mismatch — Fix: Same batch size on all inputs to a layer in one phase.
  • no-trainable-parameters — Fix: Add Layer or Conv2D before Output.
  • graph-too-large — Fix: Reduce node/link count.
  • unsafe-property — Fix: Fix invalid slice expressions or dataset filename on Input Data / Select nodes.
  • unknown-node-type — Fix: Remove or replace unsupported node types.
Warnings (export allowed)
  • preprocessing-dead-end — Fix: Mark Training or Evaluation on preprocessing outputs.
  • evaluation-entry-mismatch — Fix: Merge train and test at the same layer multi-input.
  • label-loss-mismatch — Fix: Match loss to label encoding. See Nodes → Loss & labels.
  • no-optimizer — Fix: Add Optimizer if you want a training loop.
  • multiple-optimizers — Note: Only the first Optimizer is used.
  • missing-dataset — Fix: Attach a dataset to Input Data or use synthetic data.
  • unclear-data-shape — Fix: Check CSV columns; set shape on Input Data if needed.
  • untrained-layer — Note: Layer runs only in preprocessing/evaluation, not training.
  • visualization-in-training — Note: Plot runs every training epoch (may be slow).
  • early-stopping-without-validation — Fix: Enable validation on Optimizer or turn off early stopping.
